# AppKit 迁移

## 紧凑界面（2026-10-13）

主窗口默认整窗 920×580，最小 860×540。一级导航为任务、工具、设置，共用一块玻璃，独立设置齿轮已移除；AALC 菜单（⌘,）仍可进入设置，保存的设置页编号在启动时仅展示任务页。原页面编号保持不变，队伍和主题包映射到镜牢子页。日期配队、换体策略、连接细节、快捷键和输入参数通过所属页面的三级入口编辑。日常高级配置的经验本和纽本日期配队各自折叠，启用复选框始终显示。日志默认收起，完成后操作移至“设置 → 运行参数”，删除“保持此设置”复选框，修改动作时通过现有字段默认保存；定时槽位继续使用各自的完成后配置。任务页不再预留其底栏。

设计调研以 [MAA macOS 的导航结构](https://github.com/MaaAssistantArknights/MaaMacGui/blob/master/MeoAsstMac/Navigation/ContentView.swift)和 [TaskCell](https://github.com/MaaAssistantArknights/MaaMacGui/blob/master/MeoAsstMac/Views/TaskCell.swift)为参考：原生导航、两行任务摘要、系统字号与原生表单。AALC 仅有四项既有任务，因此采用两栏，不增加 MAA 的任务类别或虚构完成状态。依照 [Apple Materials](https://developer.apple.com/design/human-interface-guidelines/materials)，玻璃用于导航和工具栏，表单采用稳定的系统背景。

表单统一左侧标签、右侧短输入、36 pt 行距及分组分隔线；长路径和数组单独排行。队伍操作收敛为编辑、权重和更多菜单，导入导出等操作保留原参数。主题编辑器按名称、权重和本层禁选对齐，保存操作固定在右上角。工具页改为紧凑的两列；四个定时任务默认收起，标题左侧的启用复选框始终可操作，点击标题展开时间、执行任务与完成后设置。折叠前沿用已有表单提交与校验，展开状态只保存在当前前端会话。定时任务选项一行排列。浅色和深色均使用系统语义颜色，缩放窗口保持控件对齐。

导航和运行控制各使用一个原生 `NSGlassEffectView`，运行区域按状态、暂停、启动排列，按钮使用原生工具栏悬停反馈；旧系统回退到标准 AppKit 材料。两组均采用 88 pt 等宽槽位、8 pt 左右内边距和 36 pt 高度，元素中心间距一致，状态文字变化不移动按钮。状态标签使用文字的自然高度居中，避免将过高的标签外框居中而使文字偏上。macOS 27 的玻璃开启公开 `effectIsInteractive`。页签静止时以文字和细线表示当前位置，仅悬停项显示底色；悬停不改变选中项。内容表单不添加玻璃，分组移除装饰描边。任务摘要与空白支持整行选择，复选框独立切换启用状态，并同步可访问性选中标记。菜单添加对应 SF Symbols，语言切换同步刷新文字、悬停说明和可访问性标签。菜单栏采用 `design/macos-menubar-dante/` 的黑色透明模板，22 pt 逻辑尺寸，包含 1×/2×表示。编辑草稿、即时配置提交、运行禁用、启停、任务顺序和版本1管道协议保持原语义。

工具栏玻璃包装层显式约束宽高，避免无固有尺寸时被 `NSToolbar` 压成不可点击的区域。原生烟测验证真实尺寸及各导航段、设置、启停按钮的 `hitTest`；回归测试使用记录回调验证 action 分发，不执行游戏任务。

四个既有 `autodaily` 槽位的定时启动命令只转发后端，不恢复主窗口；隐藏、最小化和菜单栏常驻状态保持。手动打开应用仍恢复窗口，定时协议、启动延迟、排队及任务控制保持原样。

交互回归覆盖迟到状态保留本地输入、主题包非法值恢复楼层和模式选择、仅浏览不产生未保存提示、同作用范围编辑器复用、运行时禁用连接动作、连接测试提交当前配置，以及更多菜单的语言刷新、命令参数和手工禁用。所有修复局限于前端呈现及提交边界。

前一轮验证：772 项测试通过、1 项可选 Vision 回放跳过、7 项 subtest 通过；执行冻结、ruff 与打包应用全页面烟测通过。隔离数据的原生 QA 覆盖 76 个既有配置字段、全部三级页、最小窗口、日志展开、中英文和编辑器。桌面点击验收受 AALC 电脑控制权限限制；系统玻璃工具栏无法完整缓存到 AppKit 位图，布局截图采用内容视图。验证未启动游戏任务。视觉重做前的应用备份保留在 `.runtime/app-backups/AALC-before-visual-rework.app`。

## 官方 Git 更新提示

原生更新检查只查询固定官方仓库的默认分支，不再根据包内旧版本号或 Mirror 接口判断。源码启动只读本地 HEAD、祖先和文件内容；安装包读取构建时写入的 `native-build.json`，无需附带 `.git`。官方最新提交已包含在本地、内容等价或无法确认领先时，启动不弹更新窗口。只有共同祖先及文件内容确证缺少官方变更才提示更新。手工检查显示具体比较结论，通知提供官方提交链接，并使用较小的信息窗口。

自动网络失败保持静默；重复检查复用同一请求，手工检查加入自动检查时能收到手工结果。HTTP 请求共用检查时间预算，退出中忽略迟到的更新通知。预发布版本开关不适用于提交比较，因此从原生界面隐藏，既有配置字段保留兼容。此次仅修改更新检测适配，`module/update/` 和游戏任务执行代码保持冻结。

真实只读检查确认官方提交 `b0f439321987f5f7b126ebbc424f6ef144c1bff0` 已包含在本地 `f6e8ad2` 的祖先中；本地适配领先，不应提示更新。最新 UI QA 覆盖 75 个有效原生设置字段（隐藏一个已无作用的预发布开关）。

最后渲染发现并修复原生 HTML 说明的中文乱码：明确使用 UTF-8 字符编码，并验证中文文本与官方链接。最终 831 项测试通过、1 项可选 Vision 回放跳过、7 项 subtest 通过；任务执行冻结、原生页面和编辑器 QA、ruff 与严格签名检查通过。打包后端的真实只读 Git 检查返回 `LOCAL_AHEAD`。本次修改前的安装包备份保留在 `.runtime/app-backups/AALC-before-hover-and-git-check.app`。

## 边界

`frontend_appkit/` 只处理 AppKit 控件、编辑草稿、菜单和显示；没有导入业务模块、任务、OCR 或后端服务。`backend_host/` 独占配置、任务状态与游戏连接，通过版本1的逐行 JSON 管道接受命令、发布状态。前端的 AppKit 主线程始终负责控件更新，后端控制事件通过独立事件队列串行分发。

现有 `module/`、`tasks/`、`utils/` 保留路径。任务及识别文件仅修改依赖导入；`BattleWorker` 原类体完整保留，移除同文件内 QWidget 窗口。线程、锁和信号适配在 `backend_host/runtime.py`，没有伪造 PySide6 模块。工具取消、互斥、清理和保持唤醒属于宿主/平台边界。

当前执行 AST 冻结记录在 `tests/fixtures/native_execution_baseline.json`，仅忽略 import。2026-10-14 维护的明确差异记录在 `native_execution_adaptations.json`：PlayCover 连接成功后才提交已验证 PID；删除无调用者的 macOS OCR `run_line`；OCR 缓存失效与读取共用现有锁；新手势等待结束后核验识别帧的几何版本；默认点击时长读取现有配置；macOS 定时命令添加行结束符以完整传输；商店图像规则扫描正确的 `default/share` 目录与可写覆盖层，资源失效时更新现有列表对象，成功同步后不回退加载已删除的内置模板；PlayCover 配置移除 Windows 的缩放禁用标记，原自动战斗窗口适配保留该平台语义；PlayCover 点击间隔复用既有取消信号；未识别到守备齿轮时仅初始化诊断消息，保留原分支与动作调用。测试先精确还原这些差异再核验原哈希，其余执行体继续冻结。任务等待仅替换 sleep 的平台入口，原分支与未取消时的等待时长保持，macOS 宿主停止信号可唤醒等待。原生配置入口恢复任务所需的布尔开关类型，不改寻路或第二体系策略。上游原始流程检查同样精确还原维护差异，移除的两份 Qt 界面 AST 哈希记录到 `retired_frontend_files`，没有重算任何任务预期。原启动校验、命令参数解析及主题中英文/OCR 别名同步规则已提取；新增测试验证其控制边界。

2026-10-14 后续指令将工作限定为修复当前已确认的 bug，完成验证后停止审查；不再启动 subagent，不使用 computer use。此次修正已复现的配置保存/迁移/备份、资源路径与发布布局、领奖兜底、接续战斗计数、商店选人/升级/刷新计数、第二体系奖励开关与时机、镜牢重开难度状态。每项源码差异均精确记录到 `native_execution_adaptations.json`，原始两份哈希基线保持；其他任务顺序和策略继续冻结。验证使用隔离配置、固定图像与模拟输入，不操作实际游戏。

## 当前功能

原生表单保留日常、兑换、领奖、镜牢、队伍、星光、观测饰品、普通/困难主题包与各层禁选。配置字段与原有 YAML 格式保持兼容。队伍草稿确认后保存，罪人选择顺序与数量联动，主体系舍弃和互斥策略遵循旧界面规则。已有队伍/主题配置码与 YAML 导入导出继续使用原协议。

主任务、自动战斗、截图和连接测试不能同时接管游戏连接；资源同步应用也不能与游戏任务重叠。自动战斗复用原 `BattleWorker.run/stop/_set_win` 与 `Battle.fight`，PlayCover 窗口适配只处理无意义的 PC 窗口设置/恢复。停止请求协作取消，finished 接收者只在 worker finally 与线程退出完成后推进后续动作。

单实例/定时端口62333、四组 launchd 任务、3秒启动延迟、FIFO 排队、250ms推进与收尾抑制保持。资源启动门禁完成后再处理启动参数；更新、公告和资源检查不阻塞停止/暂停命令。

原生菜单栏、Dock恢复、窗口隐藏、最小化偏好、Edit快捷键、语言与主题、全局热键、文件日志和10000行日志缓冲继续提供。

## 删除范围

删除整个 Qt `app/`、Fluent Widgets/QSS/无边框及 Qt 托盘桥接、字体注册、Qt翻译构建脚本、PySide6/Shiboken及其依赖。删除 macOS 已禁用的独立自动体力换饼工具、Windows更新器/构建与开发启动器，以及其 Windows/MirrorChyan 发布链和已无调用者的版本/预发布清理脚本。

原生界面不再创建 Windows/Android 模拟器设置、PC输入/HDR、软件更新源/CDK、截图性能基准、模拟器退出和电源操作、编队码输入。PlayCover 不支持编队码，旧开关在宿主迁移/导入边界清除；现有角色与顺序保留，原任务能力校验不变。

共享后端中的 Windows/Android执行分支、兼容配置字段、主任务换体函数、OCR回退和字体资源必须保留，以遵守执行代码冻结约束；这些不是原生界面的可用功能。macOS包排除不需要的平台二进制和 minitouch资源。

## 安装与验证

`main_macos.spec` 打包原生入口和后端，同一捆绑可执行文件以 `--backend` 启动独立进程。打包记录现有 `.runtime` 数据根，`AALC_DATA_ROOT` 可覆盖它用于隔离验证。应用标识仍为 `io.aalc.PlayCover`。

测试覆盖执行冻结、既有业务与PlayCover回放、管道EOF/错误请求、清理与退出顺序、快速停止、自动战斗参数/清理、启动失败回滚、队伍草稿、主题别名和定时控制。`--smoke-test --ui-check` 构建所有原生页面及队伍/主题编辑器，不连接游戏或发送输入。

正常退出保存失败时，宿主通知前端撤销退出并允许重试；原配置保存实现清除待保存标记后失败的情况，由宿主通过原有立即保存接口重试。前端断管或EOF后仍清理所有worker并退出，避免孤立后台进程。

这些离线检查不能代替实际游戏验收。本次迁移不自动刷本或消耗游戏资源；自动战斗的真实游戏运行结果需按实际后续使用记录。
